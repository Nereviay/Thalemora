# 洄海 · SillyTavern 自动召回插件 0.2.0

正常发送消息前，从洄海查找相关记忆并加入本轮模型 Context。聊天模型和 Key 仍由酒馆管理，插件不会写入原始聊天或同步新消息。

## 安装

1. 准备含 P8 召回接口的洄海服务。公开 v0.6.0 没有此接口；当前核心候选为 0.7.0.dev1。
2. 解压 `thalemora-sillytavern-0.2.0.zip`，将包内文件放入酒馆的 `data/<user-handle>/extensions/thalemora-recall/`。`manifest.json` 必须直接位于这个目录。
3. 刷新酒馆，确认扩展已启用。进入扩展设置，展开「洄海 · 自动召回」。
4. 填洄海服务根地址和事先签发的**专用召回凭据**，勾选「启用聊天前召回」，点「保存设置」。无需控制台或编辑源码。

本项目采用 ZIP 文件安装；它不是独立扩展 Git 仓库，不能把 Thalemora 项目根 URL 粘到酒馆的扩展 URL 安装框。压缩包包含 Apache-2.0 许可。

## 配置与停用

- 服务地址示例：`https://你的洄海地址`，不要填写 `/api/recall`，插件会追加。
- 凭据由可信管理端签发，绑定 Agent、应用来源及通道；**不要填写管理 token 或聊天模型 Key**。
- 地址和开关保存在酒馆的扩展设置中；凭据只保存在当前浏览器标签页，刷新保留，关闭标签页后需重填，不写入可同步的普通设置或聊天。浏览器相同来源的页面代码仍处于同一信任边界，密码遮挡不等于独立加密保险箱。
- 取消勾选后点保存即可关闭，并立即清空本插件注入槽位。要忘记当前凭据，关闭开关、清空凭据并保存。
- 设置区显示本轮成功、空召回或失败状态；服务错误/超时不会阻断原聊天。日志不输出凭据或召回正文。

浏览器跨源调用时，洄海设置 `THALEMORA_RECALL_CORS_ORIGIN` 为酒馆页面的精确 Origin（协议、主机和端口），默认不启用。管理 API 仍单独认证，插件不得持有管理 token。跨设备须保证可信连接，HTTPS 页面访问 HTTP 服务也可能被浏览器阻止。

## 兼容与验收边界

既有 0.1.0 召回链已在 Android 17 浏览器 / 官方 SillyTavern 1.19.0、服务器洄海、合成数据与假模型中通过相关、无关、已见、更正、401、超时六场景。0.2.0 增加设置界面与存储接线；本轮本机浏览器用合成宿主验证表单、刷新、关页、保存后召回和开关，未重新安装真实酒馆复验新面板。

每条消息最多 200 个 Unicode 字符，超长消息不截断，跳过本轮召回；约 2 秒等待超时后继续聊天。插件每轮清空并替换固定系统注入槽位，不缓存旧 revision；最终预算与裁剪由酒馆控制。不宣称纯手机首装、长时后台、所有客户端版本或聊天后自动同步已验收。

## 开发

从 Thalemora 源码根运行 `node --test integrations/sillytavern/index.test.mjs`；打包命令为 `python3 tools/package_plugins.py <产物目录>`。上游接口依据为官方 SillyTavern `06bde93` 的 getContext、扩展设置和 Prompt Interceptors，不修改酒馆本体。
