# 洄海 · Operit 自动召回插件 0.2.0

在用户正常发送前调用洄海，把相关记忆附加到当轮实际请求，界面保留用户原话。只提供召回，不代理聊天模型、不写原始聊天、不自动同步新消息。

## 安装与配置

1. 准备含 P8 接口的洄海服务及事先签发的**专用召回凭据**。公开 v0.6.0 不含该接口，当前核心候选为 0.7.0.dev1。
2. 将 `thalemora-operit-0.2.0.toolpkg` 保存到手机；在 Operit 的包管理页面选择「插件」分类，用导入文件功能选择该 `.toolpkg`。不要选择只接收 js/ts/hjson 的脚本包分类。
3. 启用插件。在 Operit 工具箱打开「洄海 · 自动召回」，填写服务根地址和专用召回凭据，打开「启用聊天前召回」，点击「保存设置」。无需编辑文件或重新打包。
4. 普通聊天照常发送。宿主先完成召回，再继续原模型请求；不需要模型主动调用记忆工具。

插件 ID 为 `org.thalemora.recall`，与旧实验 ID `org.thalemora.operit_probe` 不同。若自行装过旧实验包，应停用/删除它，避免两份适配同时召回；本项目此前的真机实验包已移除。

**当前验收状态**：0.2.0 原生设置页、持久化和打包已通过本地合成契约检查；新页面在实际 Operit 中的导入、保存和重开尚待原测试手机重新连接后复验。不要把旧版 Hook 已通过当作新设置页面也已真机通过。

## 保存与停用

- 设置保存在 Operit 本机 App 私有 SharedPreferences，重开后读取同一份配置；导出的插件包不包含设置。保存失败会显示错误，不假称成功。
- 凭据输入为密码字段；这是界面遮挡，配置并未另造加密库，仍属于 Operit App 本机信任边界。只填绑定授权来源的召回凭据，**不能填管理 token 或聊天模型 Key**。
- 关闭开关并保存可停用召回；清空地址和凭据、关闭并保存可忘记本插件配置。删除插件包不会自动代替你撤销服务端凭据，不再使用时可在洄海管理端撤销。
- 服务地址不要包含 `/api/recall`，插件会追加。手机 localhost 指向手机自身；若服务在电脑或服务器，要填可达的可信地址。

## 兼容与行为

所测宿主为官方 Operit v1.12.2。旧 0.1.1 适配在 Android 17 已有正常发送 → 真实洄海 HTTP 200 / 1274ms → 假模型实际 user Context 的证据，UI 原话保留，次轮无旧固定标记；不宣称所有版本兼容。

本版本沿用官方 Prompt Finalize 非持久化路径与 Tools.Net.http，连接/读取各 2 秒，宿主另有整链预算，不承诺总聊天固定 2 秒。空结果、错误或超时继续原消息；超过 200 个 Unicode 字符时不截断输入，跳过本轮召回。日志不输出凭据或记忆正文。

本插件不需要 Root、Shizuku、无障碍、位置、通知等额外权限。不因添加记忆服务而请求这些系统授权，也不修改 Operit 本体。

## 开发

从 Thalemora 源码根运行 `node --test integrations/operit/adapter/settings.test.mjs`；打包命令 `python3 tools/package_plugins.py <产物目录>`。包内只收录 manifest、运行代码、说明和 Apache-2.0 许可，不收录用户配置、测试或 APK。
