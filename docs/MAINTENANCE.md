# 升级、备份与恢复

数据目录由启动时的 `--data` 决定。Python 常用 `./state`，Docker 则使用命名卷；两者不是同一处。

## 升级到 v0.8.0

本版修正记忆更正/删除后的召回、补充记忆的读取与检索、索引并发与相似度计算，并收紧管理接口的默认范围。已有数据目录可直接沿用。

1. 保存原管理密钥、模型环境变量和启动配置。
2. 停止使用该数据目录的 HTTP、MCP、worker 和脚本写入。
3. 按下面步骤备份到一个新目录。
4. 在新的程序目录安装 v0.8.0，启动时指向原数据目录，使用原管理密钥。
5. 打开管理台确认资料仍在。旧索引缓存会被识别为旧格式并在首次需要时重建，期间关键词检索仍可用。

管理接口默认按应用来源过滤；需要跨应用查看旧资料时，在管理台显式切换到全局管理。调用次数预算是硬上限，token 预算只是阈值。

## 升级到 v0.7.0

本版增加独立召回、来源受限召回凭据、检索模型选择和两个聊天插件。已有历史、记忆与人工修订继续使用原数据目录。

1. 保存原管理密钥、模型环境变量和启动配置。
2. 停止使用该数据目录的 HTTP、MCP、worker 和脚本写入。
3. 按下面步骤备份到一个新目录。
4. 在新的程序目录安装 v0.7.0，启动时指向原数据目录，使用原管理密钥。
5. 打开管理台确认资料仍在，再启动需要的后台整理与客户端连接。

v0.5.0 的旧维护审计表在新版本读取时会更新结构并保留旧记录。集成到其他应用的 Python 核心应由应用自己安排升级，独立版发布不会自动替换它的依赖。

## 备份

先停止**所有**使用同一数据目录的写入，再运行：

```bash
thalemora backup ./state ./snapshot
```

`snapshot` 必须是新目录。备份包括身份、授权、历史、记忆、水系、内在状态、模型配置与用量；可能包含私人内容，请按原数据的权限保管。

**管理密钥和模型 API Key 等环境变量不在备份里**，需要另行保存。不要仅复制一个正在写入的 SQLite 文件就当作完整实例备份。

Docker 用户应先停止写入该卷的服务/worker，再用包含同一数据卷的容器执行备份，见[完整用法](USAGE.md#docker-数据备份)。不要删除卷。

## 恢复到新目录

```bash
thalemora restore ./snapshot ./restored
thalemora --data ./restored serve
```

恢复目标必须是新空目录，不会覆盖原实例。先提供管理密钥，再确认 AI 身份、来源、记忆和历史，最后恢复后台整理。

恢复会保留 Agent ID 并重新绑定档案路径；不会替你重新授权其他聊天应用。完整历史单独导入导出见[接口手册](USAGE.md#历史导出)。

## 平时看什么？

- `/health` 检查 HTTP 服务是否活着，不代表所有后台任务正常。
- 管理台「模型与用量」查看模型状态、调用量和预算。
- 查看后台整理：

```bash
thalemora --data ./state maintenance-status AGENT_ID APP_ID
```

worker 出错会记录原因并退出。修正模型配置或预算后再启动，不会无限重试。实际费用以服务商账单为准；缺少用量时不能按零费用理解。

## 出问题后

先停止有问题的写入，保留当前数据和错误信息。不要用旧快照直接覆盖含有新记忆的目录。需要回退时，先在另一个目录恢复并确认数据，再决定使用哪一份。

建议定期备份，并在升级、搬迁或修改数据来源前额外备份一次。
