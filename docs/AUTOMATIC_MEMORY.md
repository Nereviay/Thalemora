# 模型与后台整理

洄海可以手工管理记忆，也可以连接模型，在后台从已导入的历史中整理长期记忆。**打开管理台不会自动启动模型调用。**

## 不同模型分别做什么？

在管理台「模型与用量」中按用途配置：

| 用途 | 作用 | 可以选择 |
| --- | --- | --- |
| Writer | 按一段经历提炼值得保存的内容。 | API 或关闭 |
| Gatekeeper | 判断新增、补充、更正、替代或丢弃。 | API 或关闭 |
| Reflection | 为已有记忆留下整理建议。 | API 或关闭 |
| Embedding | 将文本变成向量，帮助找相关内容。 | 本地模型、API 或关闭 |
| Rerank | 对少量检索结果重新排序。 | 本地模型、API 或关闭 |

向量检索与重排互不绑定。两者关闭时使用基础词法检索；本地模型也会占用内存、空间和计算资源。

自动整理会保护人工编辑的记忆；反思只保存建议，不自行修改人格或自我认识。

## 配置 API 模型

准备支持所需协议的服务商，填写服务地址、模型名、密钥环境变量名、开关和预算。

- Writer、Gatekeeper、Reflection 使用 Chat Completions，服务需支持 JSON 输出和用量返回。
- Embedding 使用 embeddings 接口；Rerank 使用 rerank 接口，不能拿普通聊天接口代替。
- `key_env` 填环境变量的**名字**，例如 `MY_MODEL_KEY`，不是 Key 本身。真实 Key 放到运行洄海与 worker 的环境里。
- 初始模型关闭、预算为零。只有主动配置和启用后才会调用服务商。
- 调用会把所需文本发送到你选择的服务商，请按自己的隐私与费用要求选择。

例如在 Linux 启动进程前设置：

```bash
export MY_MODEL_KEY="自己的模型 API Key"
```

Windows PowerShell 使用 `$env:MY_MODEL_KEY = "自己的模型 API Key"`。容器用户还需把变量传入对应容器。不要将真实 Key 写进公开文件。

## 使用本地检索模型

先自行安装 `sentence-transformers`，并准备本地模型文件，再在管理台选择「本地模型」、填写模型目录。洄海不自动下载权重。

开发者也可以由 Python 提供已加载的模型，见[接入说明](INTEGRATION.md#本地检索模型)。

更换 Embedding 模型或向量维度时需要重建派生索引；历史原话与记忆本身不删除。第一次建索引或加载模型会比后续查询慢。

## 启动后台整理

先注册 AI、授权来源并导入历史。将命令中的 `AGENT_ID` 换成管理台显示的身份 ID，`APP_ID` 换成已授权的来源名称：

```bash
thalemora --data ./state worker AGENT_ID APP_ID --once
thalemora --data ./state worker AGENT_ID APP_ID --interval 60 --limit 1
thalemora --data ./state maintenance-status AGENT_ID APP_ID
```

第一行只处理一轮；第二行每 60 秒检查一次，默认每轮最多处理一个经历作业。两条启动命令按需要选一条运行，不必同时启动。

服务与 worker 使用**同一数据目录**，但各自是独立进程。私人来源需单独授权，并加 `--channel private`。

内容先按经历分段：20 分钟进入冷却，空闲 120 分钟后结束该段。新话不保证导入后立刻成为长期记忆；原话仍可直接搜索。

## 停止、错误与费用

- 按 `Ctrl+C` 停止 worker；当前批次结束后退出。下次从保存的进度继续。
- 模型、格式或预算出错会记录原因并退出。修正后再启动，不会无限重试或偷偷更换模型。
- 已写入的记忆不会因为后续反思失败而丢失。
- 调用次数预算按累计请求拦截；Token 预算在下一次请求前检查，最后一次可能超过阈值。
- 没收到用量时记为未知，不代表免费；实际金额以服务商账单为准。

聊天插件只请求召回，不会在发送前运行 Writer、Gatekeeper 或 Reflection。后台整理也不会自动抓取其他软件的新聊天。
