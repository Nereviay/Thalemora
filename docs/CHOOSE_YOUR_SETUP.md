# 我该怎么用洄海？先选设备，再选接入方式

> **给第一次使用的人｜2026-10-17 更新**
>
> 洄海是长期记忆与连续性系统，不是聊天 App。它可以独立管理记忆，也能通过聊天软件开放的接口提供记忆；不会自动读取任意软件里的全部聊天。
>
> **公开可安装版仍为 v0.6.0。P8 自动召回已在隔离环境验收，尚未集成、打包或发布。** Android 浏览器中的 SillyTavern 与 Operit v1.12.2 都有真实发送证据，但还不是普通用户可直接安装的正式连接器。

## ① 我现在有什么设备？

| 你的情况 | 从哪里开始 | 已验证范围 |
| --- | --- | --- |
| **只有 Android 手机** | [Android 工作区试装](INSTALL_ANDROID.md) | RikkaHub 2.5.6 工作区短时运行、MCP 九工具发现通过；完全脱离电脑的首装和长时后台尚未验收 |
| **Android 手机，另有电脑或服务器** | 先在 [Windows](INSTALL_WINDOWS.md) / [Linux 或 VPS](INSTALL_LINUX.md) 运行洄海，再看下方客户端表 | 手机聊天、其他设备运行记忆服务的接入已有实证；需要配置网络和对应适配 |
| **Windows 电脑** | [Windows 安装](INSTALL_WINDOWS.md) | 一台电脑的原生 Python 路线完成 v0.5.0 首装、网页操作与重开回读；Windows Docker Desktop 未验 |
| **Linux 电脑 / VPS** | [Linux 安装](INSTALL_LINUX.md) + [使用手册](P4_USAGE.md) | Python 与 Docker/Compose 有隔离验收；远程地址、HTTPS 或可信网络需自行配置 |
| **只有 iPhone / iPad** | 暂无已验证的本机安装路线 | 如另有电脑/服务器，可按聊天客户端接口评估；不能照抄 Android 工作区教程 |
| **自己开发 Agent** | [Python / HTTP / MCP](P4_USAGE.md)；开发版另见 [召回协议](P8_RECALL_CONNECTOR.md) | 一套核心与协议，客户端只处理必要适配 |

手机的 `127.0.0.1` 指向手机自己，不能用它直接访问 VPS。**聊天软件装在手机上，不要求记忆服务也装在手机上。**

## ② 我要哪种记忆功能？

| 想做到的事 | 当前能否做到 | 需要什么 |
| --- | --- | --- |
| **查看原话，手工创建或更正记忆** | 公开 v0.6.0 支持 | 服务已运行，Agent 和来源已授权；无需模型 Key |
| **从历史自动整理长期记忆** | 公开 v0.6.0 有独立 worker | 已导入可信历史，按用途配置并显式启用模型；不会自动抓取其他 App 聊天 |
| **让聊天模型调用记忆工具** | 公开 v0.6.0 提供 MCP 九工具 | 客户端启用 MCP、认证和授权；是否调用由客户端/模型决定 |
| **发消息时自动找记忆并放入模型 Context** | P8 隔离验收通过，未发布 | 客户端有发送前修改 Context 的接口，并装好对应适配 |
| **新聊天自动保存到洄海** | 需宿主单独接线 | 可靠的消息落地事件与授权同步；本轮两个插件没有实现这件事 |

这四种状态要分别确认：

1. 管理台可访问、能搜原话：**服务可用**。
2. 模型实际成功调用工具：**工具接入可用**；仅列出九工具还不够。
3. 正常发送后，实际模型请求含本轮召回：**自动注入可用**。
4. 消息保存后，洄海出现对应事件及版本：**聊天同步可用**；仍不等于已提炼成长期记忆。

## ③ 我的聊天软件兼容吗？

| 客户端 / 所测版本 | 实际结果 | 使用限制 |
| --- | --- | --- |
| **SillyTavern 1.19.0，Android 17 浏览器** | 正常发送自动触发插件，真实洄海召回进入假模型实际 Context；相关、无关、已见、更正、401、超时六场景通过 | 酒馆和洄海在服务器运行，手机通过测试转发访问；不是手机本地首装。适配未发布，配置仍需开发者操作 |
| **Operit 官方 v1.12.2，Android 17** | 外部 ToolPkg 正常发送前调用洄海；记忆附加到当轮 user 请求，界面保留用户原话，下一轮没有前轮固定标记 | 仅最小实验通过；配置源码默认空白，尚无图形配置页或正式安装包。未读取 App 私有数据库，未做全部异常分支验证 |
| **RikkaHub 2.5.6，Android** | 工作区运行与 MCP 认证、九工具发现通过 | 模型真实工具调用未验；向第三方开放的发送前 Context 接口尚未确认，自动注入未验收 |
| **其他客户端 / 版本** | 未验证 | 按实际接口和版本检查，不能因为写着“支持插件”就认定兼容 |

SillyTavern 本轮相关召回 HTTP 约 **1271ms**（Hook 1272ms）；Operit 插件 HTTP 约 **1274ms**。这是包含测试网络转发的单次观测，不是所有设备的速度承诺，也不包含完整模型回复耗时。

**Operit 可以做这种插件。** 本次用了官方发送前 Prompt Finalize 接口，没有修改 App 本体。早先引用的 `bypassPromptHooks` 属于 Token 估算路径，不能据此认定普通发送绕过插件；用户 Issue 也不等于官方确认所有插件失效。

### 接入前要准备什么？

- 运行含 P8 接口的洄海开发版；公开 v0.6.0 没有 `/api/recall` 与受限召回 token。
- 注册 Agent、授权来源，由可信管理端签发**专用召回 token**；插件不能填管理 token。
- 让客户端能访问服务地址。浏览器跨源调用还需配置精确可信 Origin；详见 [开发版协议](P8_RECALL_CONNECTOR.md)。
- 安装对应宿主适配。SillyTavern 实验配置只在当前页面内存，刷新需重填；Operit 实验需要开发者在私有打包副本填写 URL/token。**现阶段没有供普通用户直接照做的正式插件安装流程。**

本轮临时插件、测试服务和转发均已撤除，不能继续使用测试地址。后续配置界面、打包、分支集成与发布尚待处理。

## ④ 没有发送前插件接口，还能用吗？

| 软件提供什么 | 可以怎么接 |
| --- | --- |
| **MCP 工具接口** | 按 [MCP 配置](P4_USAGE.md#python--http--mcp) 连接；可以调用记忆工具，不保证每轮自动调用 |
| **Linux 工作区 / Termux** | 可作为运行服务的环境；它本身不能改变其他聊天软件的 Context，兼容与后台需另验 |
| **仅能修改模型 API 地址** | 可考虑未来的 API 代理路线；目前洄海没有交付该代理产品 |
| **世界书 / 固定提示词** | 可使用客户端已有的静态内容机制，不等同于每轮动态检索 |
| **以上都没有** | 仍可独立使用 Web 管理台，手动复制检索结果 |

发送前接口是当前两个适配采用的方式，并非唯一架构。通用的是记忆核心和召回协议，宿主插件包不能跨所有 App 通装；也无需为每款 App 重写记忆系统。

## ⑤ 从零开始的顺序与限制

1. 按设备进入安装指南，让公开版先独立运行。
2. 保存自己的管理 token，注册 Agent、授权来源，导入[合成练习历史](examples/p4_history.json)，确认能回查原话与人工记忆。
3. 有 MCP 的按 [使用手册](P4_USAGE.md) 接入；需要自动注入的先核对上方版本和未发布限制，不直接套用公开版命令。
4. 分开验证服务、工具、实际 Context 和聊天同步。

浏览、导入、词法检索、人工记忆无需模型 Key；后台整理需要配置模型。Embedding / Rerank 本地、API 或关闭三模式属于未发布 P8，启用模型会增加资源与耗时。聊天前召回不运行 Writer/Gatekeeper，后台整理也不应阻塞当轮回复。

管理 token 具有实例权限，不要公开；插件只持有授权来源的召回 token。备份应先停写，Python 数据目录与 Docker 卷各自保存；网盘只存文件，不运行服务，当前没有自动网盘备份接口。

纯手机首装/恢复、长时熄屏后台、iOS 本地运行、跨 App 聊天自动同步和一行命令自动安装注册，都不能因这次注入成功而算完成。
