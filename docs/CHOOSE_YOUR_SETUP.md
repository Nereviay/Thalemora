# 我该怎么用洄海？先选设备，再选接入方式

> **给第一次使用的人｜2026-10-16**
>
> 洄海是**长期记忆与连续性系统**，不是聊天 App，也不会自动读到你在其他软件里的全部聊天。它可以独立管理记忆，也可以通过其他软件允许的接口提供记忆。
>
> **先看版本**：公开可安装版是 **v0.6.0**；聊天前自动召回模块和专用连接凭据目前只在**未公开的 P8 隔离代码**中通过合成测试。真实手机聊天前注入还没有验收。下文将二者严格分开。

## ① 我现在有什么设备？

| 你的情况 | 推荐阅读 | 当前已经验证到哪一步 |
| --- | --- | --- |
| **只有 Android 手机** | [Android 手机试装](INSTALL_ANDROID.md) | RikkaHub 2.5.6 的 Linux 工作区安装、短时服务运行和九个 MCP 工具发现有真机记录；**没有**完成完全脱离电脑的一键首装，也没有真实聊天前自动注入 |
| **Windows 电脑** | [Windows 安装](INSTALL_WINDOWS.md) | Python 路线已在一台电脑完成过 v0.5.0 的安装、网页操作与重启；公开 v0.6.0 沿用安装结构，**不保证所有 Windows/Docker 环境已测** |
| **Linux 电脑** | [Linux 安装](INSTALL_LINUX.md) | Python 与 Docker/Compose 有隔离验收，首次使用仍要安装运行环境 |
| **自己的 VPS / 服务器** | [Linux 安装](INSTALL_LINUX.md) + [使用手册](P4_USAGE.md) | 服务器端运行同一套洄海；**远程连接、HTTPS、访问权限需要自己配置**，不是填写手机或电脑的 `localhost` |
| **iPhone / iPad 只有本机** | 暂无已验证的本机安装方法 | 不能套用 Android 工作区教程；若你另有电脑/服务器，可从其连接能力单独评估 |
| **想给自己的 Agent 接入** | [Python/HTTP/MCP 说明](P4_USAGE.md) | 公开版可调用已有接口；P8 的[聊天前召回协议](P8_RECALL_CONNECTOR.md)仅在隔离开发版存在 |

**只想看看洄海长什么样？** 选一条已验证的电脑/服务器安装路线，按 [第一次使用教程](GETTING_STARTED.md) 导入**合成示例**、检索原话、创建人工记忆。不要一开始就导入私人聊天或购买模型 API。

## ② 我要的是哪种“记忆功能”？

| 想做到的事 | 目前能否做到 | 必要条件 / 不能误会的地方 |
| --- | --- | --- |
| **查看原话、手工建立或更正记忆** | **公开 v0.6.0 已支持** | 洄海已运行，并且相关 Agent 与来源已授权；无模型 Key 可用 |
| **从已有历史自动整理长期记忆** | **公开 v0.6.0 有独立 worker** | 必须有可信、已导入的历史，按用途配置真实模型并显式启用 worker；**不是**自动读取任意聊天 App 的全部新消息 |
| **在聊天里主动调用记忆工具** | **公开 v0.6.0 支持 MCP 接口** | 客户端支持对应 MCP、完成认证和来源授权；是否调用取决于客户端/模型，**不保证每轮使用** |
| **每轮聊天前自动召回并注入 Context** | **P8 隔离版有召回模块和 HTTP 合同，手机未打通** | 聊天软件必须开放真正的发送前可执行 Hook，或者后续实现其他获用户选择的接入方式；光有 MCP 或工作区不够 |
| **新聊天自动进入洄海档案** | **不保证** | 宿主需要提供可靠的消息**已保存**事件并按授权同步；能在聊天前读取输入并不意味着能安全记录实际聊天 |
| **直接使用 AI、不安装记忆服务** | **洄海不是这种产品** | 聊天模型仍由你原来的聊天软件或 Agent 提供，洄海负责记忆 |

**理解三个不同状态**：**已安装洄海 ≠ 已连接聊天软件 ≠ 聊天时自动召回。**

## ③ 你的聊天软件支持什么连接能力？

先打开聊天软件的“插件 / 扩展 / MCP / 工作区 / 模型 API”设置，不要只看它能不能填写网址。

| 软件有的能力 | 连接方式 | 实际效果及限制 |
| --- | --- | --- |
| **真正的发送前 Prompt/Context Hook** | 将来装入洄海的轻量连接插件/适配器；插件调用统一召回接口 | **目标：无感自动召回**；每款软件必须验证 Hook 能实际改变**送给模型的**消息。**通用的是洄海核心和协议，不保证同一个插件包能跨所有 App 安装** |
| **只有 MCP 工具接口** | 按 [MCP 配置](P4_USAGE.md#python--http--mcp) 连接服务 | 可以搜索、读取及执行获授权的记忆操作；模型可能完全不调用，不是确定性的“每轮自动” |
| **有 Linux 工作区 / Termux** | 在该运行环境中安装并启动洄海，再按客户端能力连接 | 工作区**只是运行环境**；它不能自动修改其他聊天软件的 Context；手机后台/耗电/空间仍需实测 |
| **只允许更改聊天模型 API 地址** | 未来可能选择 **可选 API 代理** | 可以在转发模型请求前加入记忆，但**洄海目前没提供该正式代理产品**；会引入额外连接、网络和凭据管理 |
| **能导入世界书/固定提示词** | 仅作为客户端已有能力的兼容方案 | 静态规则或预同步内容不等同于每轮由洄海检索、判断、去重 |
| **以上都没有** | 独立 Web 管理台或用户显式复制结果 | 仍能管理记忆，但**不能无感接入聊天** |

**关于“粘贴一串就安装/注册”：** 这是计划优化的**电脑/服务器体验**，可能由安装脚本、`uvx`/`npx` 运行命令、客户端的 `mcp add` 命令组合完成。**现在尚未交付一行命令自动安装并向所有客户端注册**；不同客户端可能没有可自动配置的入口。手机插件安装则是另一条流程。

## ④ 从零开始的正确顺序

1. **先选设备**，照上表进入对应安装指南；确认版本和需要的 Python/Docker/手机工作区条件。不要把 VPS 地址写成手机的 `127.0.0.1`。
2. **先让洄海独立运行**，打开 Web 管理台，使用你自己保存的管理 token。
3. **注册 Agent 并授权来源**，先导入两条[练习历史](examples/p4_history.json)，确认能搜到原话、建立人工 Memory。
4. **再按客户端功能连接**：使用 MCP 的读 [MCP 配置](P4_USAGE.md#python--http--mcp)；自己开发 Agent 的读 [接口说明](P4_USAGE.md)；真正有发送前 Hook 的才评估 [P8 协议](P8_RECALL_CONNECTOR.md)（**未公开版，不可按公开 v0.6.0 直接照做**）。
5. **分开验证结果**：①服务可访问；②工具或接口能请求；③相关记忆真正在上游 Context 出现；④新消息是否被可靠保存。四件事各自确认，不能相互替代。

## ⑤ 开始前必须知道的限制

| 主题 | 现在需要知道的事实 |
| --- | --- |
| **模型费用** | 浏览、导入、词法搜索和人工记忆**不需要模型 Key**；后台自动整理需要按用途配置模型。Embedding/Rerank 本地/API/关闭三模式属于**未发布 P8 隔离版**；本地模型也会占空间、内存和算力 |
| **隐私与认证** | `THALEMORA_TOKEN` 是**整个实例的管理权限**，不要公开。P8 隔离版新增**限定来源的召回 token**，未包含在 v0.6.0。跨设备访问须自行保障 HTTPS/可信网络 |
| **聊天数据** | 不自动从任意 App 读取聊天记录。已导入原话、已写入长期 Memory、模型回复看见记忆，是三件不同的事 |
| **存储和备份** | Python 的数据目录与 Docker 数据卷不同。备份前应停写；**网盘是文件存储，不会自己运行洄海**；目前没有已验收的自动网盘备份/跨手机迁移 |
| **速度与质量** | 本地基础搜索可无需模型，但不等于语义检索；启用 API、本地模型或 Rerank 会增加运算/网络耗时。P8-4 **没有真实手机注入速度记录**，不保证毫秒级响应 |
| **设备支持** | Windows Python 和 Linux 的对应路线有有限验证；Android 仅有工作区试验，**长时间熄屏运行、纯手机首装/恢复与真实 Hook 未通过**；iOS 本地路径未验证 |
| **兼容性** | “有插件”未必有发送前修改 Context 的权限；“MCP 已连接”也未必自动调用。Operit 不作为默认依赖，RikkaHub 的可用发送前第三方 Hook 未确认 |
| **版本** | **公开 v0.6.0** 是可安装的当前版本。P8-1～3 为本地隔离研发结果，P8-4 真实客户端 HOLD；**不要把正在开发的召回入口、受限 token 或插件写成公开已可使用** |
