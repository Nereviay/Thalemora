# 选择适合你的用法

先决定**洄海服务运行在哪里**，再决定**聊天软件怎样连接**。这两件事可以在不同设备上完成。

## 服务装在哪里？

| 你的设备 | 使用方式 |
| --- | --- |
| Windows 电脑 | 按 [Windows 教程](INSTALL_WINDOWS.md)安装 Python 版，浏览器管理记忆。 |
| Linux 电脑或 VPS | 按 [Linux 教程](INSTALL_LINUX.md)安装 Python 版或 Docker 版。 |
| Android 手机，另有电脑或服务器 | 服务运行在电脑或服务器，手机通过插件或 MCP 连接。 |
| 只有 Android 手机 | 可在 Linux 工作区手动安装，见 [Android 说明](INSTALL_ANDROID.md)；需要终端操作并自行管理后台运行。 |
| 只有 iPhone / iPad | 目前没有本机安装教程；可以连接自己其他设备上的服务，具体取决于聊天应用的接口。 |

手机的 `127.0.0.1` 指手机本身，不能用来直接访问电脑或 VPS。

## 想让记忆怎样工作？

| 你想做到的事 | 需要什么 |
| --- | --- |
| 看原话、手工保存或更正记忆 | 运行服务，打开网页管理台。 |
| 从已有历史自动整理记忆 | 导入历史，配置模型并启动[后台整理](AUTOMATIC_MEMORY.md)。 |
| 让 AI 调用记忆工具 | 聊天软件支持并启用 [MCP](MCP.md)。 |
| 发消息前自动找记忆 | 安装对应[插件](PLUGIN_SETUP.md)，或让自己的应用调用[召回 API](RECALL_API.md)。 |
| 把新聊天自动保存到洄海 | 应用在消息保存后，按授权调用历史导入或同步接口。 |

安装成功、工具连上、自动召回和聊天同步是不同功能。MCP 是否调用由应用和模型决定；两个现有插件只做召回，不负责聊天同步。

## 连接哪种客户端？

| 客户端 | 连接方式 |
| --- | --- |
| SillyTavern 1.19.0 | 提供发送前自动召回插件，在扩展设置填写地址和专用凭据。 |
| Operit 1.12.2 | 提供 toolpkg 插件，导入后在工具箱配置。 |
| RikkaHub | 可通过 Streamable HTTP MCP 连接；本项目不提供它的每轮自动注入插件。 |
| 其他客户端 | 有 MCP 就连接工具；有发送前扩展接口就可以自行适配。 |
| 没有这些接口的客户端 | 仍可使用独立管理台，再手动复制所需内容。 |

## 费用、数据和备份

- 无模型 Key 可使用基础功能；启用模型或第三方 API 前，先查看对应费用与预算设置。
- 不会自动读取其他 App 的全部聊天，需要导入或由应用按授权同步。
- 每个 AI 有独立身份；不同来源和私人通道分别授权。
- 网盘可以存备份，不能代替运行服务；当前不提供自动网盘同步。
- 目前不提供通用模型 API 代理、手机一键安装或跨所有客户端的通装插件。

选好路线后，继续[第一次使用](GETTING_STARTED.md)。
