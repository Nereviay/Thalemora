# 只有 Android 手机：工作区试装洄海（RikkaHub 已做有限验证）

> 本页展示**已在 RikkaHub 2.5.6 有限真机验证过的一条 Android 工作区路线**，不是说只有 RikkaHub 能运行洄海；其它工作区环境未据此确认兼容。**公开 v0.6.0** 有 HTTP MCP 九工具；旧 v0.4.0 不支持。这不是一键安装，只有手机的完整独立首装尚未验证，**MCP 连接不会自动把每轮记忆放入 Context**。

这说明技术路线**可行**，不是“普通人已可一键安装”。此次真机使用了电脑辅助传输 PRE6-2 实验候选源码包；并非从零开始的手机独立下载流程。

## 第一步：建立手机工作区（实际验证过）

1. 打开 RikkaHub → **设置 → 扩展管理 → 工作区**。
2. 点击右下角 **＋**，建一个新工作区，例如 `ThalemoraTest`（英文名称）。
3. 点进刚创建的工作区，选择 **安装 Rootfs**。这里的 Rootfs 就是一个“给洄海运行程序用的小 Linux 环境”。
4. 安装完成后，在工作区右上角打开 **终端**，确认看到类似 `root@localhost:/workspace#` 的文字；终端就是输入下一步命令的地方。

以上菜单路径来自 [RikkaHub 官方工作区指南](https://docs.rikka-ai.com/zh/extensions/workspace)，在本次 RikkaHub 2.5.6 真机也得到验证。不要在原来的私人聊天工作区里试装；先用全新练习工作区。

**下载提醒**：本次 Ubuntu 基础文件约 **29.9 MB**；`apt-get update` 的下载约 **37.4 MB**；单独安装 Python 的那轮预计下载约 **119 MB**、额外磁盘约 **409 MB**，不含后续 Python 依赖和运行数据。网络流量、最终安装占用会因版本不同而变化，不能把上述数字相加当作精确总磁盘大小。

## 第二步：安装 Python（实际验证过）

在工作区终端**逐行**输入或粘贴，等前一行结束后再运行下一行：

```bash
apt-get update
apt-get install -y python3 python3-venv python3-pip
python3 --version
```

本次真机显示 `Python 3.12.3`；你的结果可能不同。如果系统提示下载安装失败、空间不足或找不到软件包，先停下，不要反复重装 Rootfs。

**当前 v0.6.0 已公开发布**，可以从 GitHub Release 或相应版本标签获取源码。但此前真机验证是电脑传入的受控 HTTP MCP 候选，**尚未完成“只用手机下载公开 v0.6.0、安装依赖、连上 MCP”的全程首装**。此处不伪造一键安装已通过，后续再补实际验证与命令。

安装公开 v0.6.0 时还需要创建 Python 虚拟环境、安装依赖、启动 `thalemora serve`。首次真机曾成功执行这条安装链，但其测试文件来自受控候选，不来自公开 v0.4.0。

## 手机上的 MCP 连接步骤

> 以下步骤来自旧测试候选的实测经验，仅证明 MCP 连接和工具发现；**不等于模型每轮自动召回**。

**前提**：本机洄海新版已装好且正在工作区终端运行；HTTP 服务监听手机的 `127.0.0.1:8765`。在 PRE6-3 测试中，用户手动启动服务；测试完成后该服务已关闭。别把 RikkaHub 的 localhost 当成远程 VPS。

1. 进入 RikkaHub **设置 → MCP → 添加**。
2. 类型选择 **Streamable HTTP**，**不是 SSE**。
3. 名称用 `ThalemoraMCP` 这样的**纯英文字母/数字**（此次版本拒绝带连字符的名称）。
4. 地址输入：

   ```text
   http://127.0.0.1:8765/mcp
   ```

5. 在请求头里新增一行，**名称**填写 `Authorization`，**值**填写：

   ```text
   Bearer 这里替换成你自己保存的管理密钥
   ```

   `Bearer` 与管理密钥中间**恰好一个英文空格**。实测 Android 自动输入曾吞掉这个空格，导致认证失败；请点回输入框确认，而不是反复改密钥。**不要把管理密钥填进 URL**。
6. 保存后到 MCP 服务器的工具列表检查。测试候选实际发现以下九项：`list_agents`、`search`、`history`、`inner_state`、`memory`、`evidence`、`import_history`、`remember`、`revise_memory`。
7. **如需给某个聊天助手使用**，按 [RikkaHub 官方 MCP 指南](https://docs.rikka-ai.com/zh/extensions/mcp) 到**助手设置**中启用这个 MCP 服务。注意：此前只验证了客户端连接和工具列表，没有验证模型在聊天中真正调用这些工具。

**重要**：这个管理密钥具有整个洄海实例的管理权限，不是只读/单个应用的受限凭据。当前没有“手机扫一下二维码即可安全自动授权”的功能。MCP 连接成功也**不会自动导入聊天历史**；需要授权对应来源并按实际应用能力导入。

## 连接失败先看这四项

| 表现 | 最可能先检查 |
| --- | --- |
| 显示连接失败或无法访问 | Linux 工作区里的 Python 服务还在运行吗？关闭终端/系统杀后台后可能断开 |
| 提示认证失败 / HTTP 401 | `Authorization` 头值是否为 `Bearer`、一个空格、自己的管理密钥 |
| 显示已连接，但找不到九工具 | 是否装的是旧 v0.4.0？九工具要求 v0.5.0 或以后 |
| 九工具看到了，但聊天里没用 | 还需在目标助手启用 MCP，而且**聊天模型真实调用路径尚未在本项目验收** |

## 怎么停用、备份和换手机

- 测试结束后在工作区终端按 `Ctrl+C` 停止服务；如有不再使用的临时 MCP 条目，可在 RikkaHub 的 MCP 列表中删除。**删除 MCP 配置不等于删除记忆数据**。
- 工作区中的记忆文件在自己的 `--data` 数据目录中。正式备份须**先停写**，再运行 `thalemora backup <原数据目录> <新快照目录>`；RikkaHub 官方文件管理器支持从工作区导出文件。此处仅为已实现功能与文件导出的组合说明，**完整手机备份→新手机恢复的端到端流程尚未真机验收**。
- 只把备份上传百度云、夸克或 Google Drive，不会自动让洄海在另一个手机上运行；必须有实际运行环境，并且目前**没有自动网盘备份接口**。
- 手机长期后台稳定性、耗电、自动启动，以及真正适合普通用户的无终端安装步骤都未完成，已在 [安装难点清单](INSTALL_FRICTION.md) 登记，不应在当前阶段宣称“手机稳定常驻”。

如果只是想体验基础管理台，可以先在能运行 Python 或 Docker 的电脑上按 [入门指南](GETTING_STARTED.md) 操作。只有手机、愿意手动操作的人可以参考以上试装步骤，但完整独立安装与后台可靠性**未通过验收**；不要误以为 v0.6.0 提供现成 APK、无终端安装或聊天前自动记忆。
