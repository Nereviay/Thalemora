# 安装难点与后续简化清单

> 2026-10-15 PRE6-5 产生，2026-10-17 根据安装、发布与接入实证更新的**产品待办台账**。目的不是教用户忍受麻烦，而是明确下一轮安装体验应该减少哪些负担。按真实性区分 **[真机遇到]、[已有实现事实]、[尚未在平台实测]**；没有用户调查数据的条目不冒充“多数用户都会遇到”。

## 衡量标准

- **P0｜实际无法完成想做的事**：版本缺能力、缺少必要交付，教程再详细也无法解决。
- **P1｜非技术用户很难独立完成**：需要终端、安装运行时、密钥及权限配置、多步骤排错，且没有易用的向导。
- **P2｜能完成但易迷失/迁移风险大**：难理解版本/数据根/停止服务/备份，或平台尚无首装验收。

建议下一轮安装体验实测统一记录：**入口 → 每步点击/命令次数 → 需要额外安装的软件与下载量 → 是否完成“首次有记忆可回看” → 是否可以重新打开和恢复 → 实际失败截图或日志**。不凭空设“几分钟搞定”“低于某 MB”的数字，先做单设备真实测量。

## 已发现的难点（按优先级）

| 编号 | 优先级 | 影响谁 / 发生在哪一步 | 真实依据与当前状态 | 后续优化方向与验收条件 |
| --- | --- | --- | --- | --- |
| INST-01 | **P0** | 只有手机的人：安装公开代码后想使用 RikkaHub HTTP MCP | **[发布部分已解决]** 公开 v0.6.0 已含九工具/Streamable HTTP；手机独立首装仍未验收 | 不再重复安排发布 v0.5.0；后续验证只用手机自行下载、安装和连接，才宣称完整首装通过 |
| INST-02 | **P1** | 纯手机用户：Rootfs → Python → 源码 → venv → pip → 服务 → MCP 表单 | **[真机遇到]** RikkaHub Ubuntu 工作区和 Python 可装，但整个流程需要终端命令及手动服务器启动，且试装借助电脑传输候选 | **安装引导一体化**：研究在已有 RikkaHub 工作区提供有版本校验的短命令安装器/可导入工作区文件和逐步状态检查；测试“仅用手机、不借助电脑”从空白到九工具连接 |
| INST-03 | **P1** | 手机用户：下载量与本机空间 | **[真机遇到]** Ubuntu Rootfs 下载约 29.9MB、apt update 约 37.4MB、Python 安装预计下载约 119MB、额外约 409MB；Python pip 依赖与数据实际增量未严格测量 | 先获取同条件安装前后磁盘增量，再研究最小依赖/缓存回收；**不提前许诺**可省多少空间，不私自换框架 |
| INST-04 | **P1** | 手机用户：连接时填写 MCP 名称、URL 和 Bearer 请求头 | **[真机遇到]** RikkaHub 2.5.6 名称拒绝连字符；Android 输入吞掉 `Bearer` 后面的空格，首轮 401。改为英数字及重新输入空格后握手和九工具发现 PASS | **一键配置/导入**：探索用户本地可导入的 MCP 配置模板与无私钥的 URL 校验；导入后仍由用户在本机填写管理密钥。验收不用 ADB、手动排错也能连上 |
| INST-05 | **P1** | 所有本地用户：保存/重输管理密钥；RikkaHub 直接持有 owner 管理权限 | **[已有实现事实]** 当前 `THALEMORA_TOKEN` 是整个实例 owner，非应用级受限凭据；首次与下次使用要保证一致，不能将 token 贴进公开日志 | 评估首次运行的本机安全 token 保存/查看/粘贴引导；P8 未发布版已有来源受限 Recall token，但它不能替代 MCP 所需的管理认证，不把召回权限冒充通用工具权限。测试重启后配置仍有效且不会外泄 |
| INST-06 | **P1** | 手机用户：退后台、熄屏后服务是否继续存在 | **[真机实测 + 未完成]** 有限验证仅后台约 68 秒服务 HTTP 200；曾见连接短时 Transport closed/重连，**长时熄屏、省电、自动恢复未验** | 继续 PRE6-3：同条件资源/电量及长时稳定性/受控重启；确认约束后评估“打开 App 即启动服务/自动拉起”，不提前承诺常驻 |
| INST-07 | **P1** | Windows 用户：初次装 Python、依赖或 Docker/WSL2、启动命令 | **[原生 Python 已有限实测]** 一台 Windows 电脑完成公开 v0.5.0 隔离首装、网页操作、重开回读和停写备份；Docker Desktop 未测 | 现阶段推荐已有证据的 Python 路线；不为补表格重复安装另一套环境。图形启动器尚未交付 |
| INST-08 | **P1** | 用户以为“装好=自动从聊天里产生长期记忆” | **[公开 v0.6.0 已有 worker]** 可配置模型并后台整理已导入历史；不能自动消费任意 App 聊天。P8 自动注入验收不等于聊天后同步 | 后续面向具体宿主补可靠落地事件和授权同步；导入、整理、召回分别展示，不重做已有 worker |
| INST-09 | **P2** | Windows / Linux 用户：不知道数据存哪里、关掉后怎么恢复 | **[已有实现事实]** Python 的 `./state` 与 Docker 的命名卷是两个不同数据根；管理密钥保存在环境中，普通用户容易误以为换命令就会读取相同数据库 | 首次使用标识当前数据根、备份入口和明确的“停止服务”按钮/提示；通过关停—重启—换机器真实恢复验证，未验前不声称图形化迁移 |
| INST-10 | **P2** | 手机用户：换手机或网盘备份 | **[已有实现事实 + 未实测]** 当前只有停写 CLI 备份/恢复；RikkaHub 可导出工作区文件，**但手机→新手机端到端恢复未验**；没有云盘自动同步 | 验证全程脱离电脑的手机导出/导入/恢复，之后再评估可选云盘 provider；云盘不能代替计算/运行时 |
| INST-11 | **P2** | 用户需要记住 Agent ID、app/channel、JSON envelope 才能导入第三方历史 | **[已有界面事实]** 管理台已有注册/授权及示例导入，第三方自动获取历史与应用权限尚未接线；长期字段 JSON 难理解 | 做“先体验示例、再选择来源、导入向导”流程，统一进度反馈；不同应用的授权与私有通道仍按正式权限规则 |
| INST-12 | **P2** | 移动端查看管理台与实际聊天应用的界面区分 | **[浏览器合成验证]** 375px 宽管理台无横向溢出，但截图是窄屏网页；不等于 Android App 已装或聊天已接入 | 教程分别标示 Web 管理台截图、RikkaHub 实机菜单和 MCP 状态；未来在真实 Android 浏览器上做触控与小屏首用测试 |

| INST-13 | **P1** | 想在酒馆 / Operit 每轮自动使用洄海的用户 | **[真机实证，未产品化]** 两个宿主已有发送前注入证据；P8 未发布；0.2.0 设置与本地包已实现，酒馆合成浏览器检查通过，Operit 新页面普通导入/保存/重开通过 | 按授权安排公开分发；不重开已通过的手机核心或配置验收；不再把“是否能注入”当未知重测，不把实验包写成普通用户成品 |

## 优化实施顺序（不自动开工）

公开 MCP 发布与 Windows Python 首装已有结果；下一次按实际授权选择插件配置/打包（INST-13）或手机安装体验（INST-02/03/04/06），再处理具体来源同步、备份迁移与导入引导（INST-08/09/10/11）。不自动启动所有待办。

- PRE6-6 发布已完成；P8 接口、插件与新版文档尚未集成公开，不沿用旧发布授权自动发新版。
- PRE6-3 手机首装、长时后台和聊天 MCP 真调用仍 HOLD，本次文档更新不启动补测。
- 专门的“简化安装 / Setup UX”任务需等首次从零安装的失败/操作统计再立项，不能为了一键而并行做两个运行环境、另做 APK 或改动正式 Memory Owner。
- **P6 是念念生产集成**，上述普通用户安装体验不当成 P6 的隐性阻断；但对外宣称易用或手机正式支持前，要完成相应平台真实验收。

更多具体操作见 [普通用户入门](GETTING_STARTED.md)、[Windows](INSTALL_WINDOWS.md)、[Linux](INSTALL_LINUX.md) 和 [手机试装](INSTALL_ANDROID.md)。
