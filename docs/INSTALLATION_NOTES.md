# 安装常见问题

## 运行服务和连接聊天，是两步

洄海需要 Python 或 Docker 运行。插件和 MCP 负责连接正在运行的服务，不能代替服务本身。

电脑或服务器可以运行洄海，手机只负责聊天。仅有手机时，也可手动准备 Linux 工作区，但没有一键 APK 或自动后台运行方案。

## 我有地址，为什么打不开？

- `127.0.0.1` 和 `localhost` 只代表当前设备。
- 服务默认只监听本机，跨设备需要可信连接或反向代理。
- HTTPS 酒馆页面访问 HTTP 洄海可能被浏览器阻止。
- 浏览器跨源调用还需设置精确的 `THALEMORA_RECALL_CORS_ORIGIN`，见[插件教程](PLUGIN_SETUP.md)。

## 两种密钥不要混用

| 密钥 | 用在哪里 |
| --- | --- |
| 管理密钥 `THALEMORA_TOKEN` | 管理台、管理 API、HTTP MCP。 |
| 专用召回凭据 | 酒馆/Operit 插件，仅访问指定来源的召回。 |

插件不能拿管理密钥代替召回凭据。模型 API Key 是另一回事，只在模型配置对应的进程环境中设置。

## 重开后找不到原数据

确认启动时指向原 `--data` 目录。换了程序目录，`./state` 也可能变成另一个位置；可以使用数据目录绝对路径。

Docker 命名卷与 Python 文件夹不同。更新前按[维护说明](MAINTENANCE.md)备份，不用删数据解决问题。

## 能搜索，却没有自动记忆

导入只保存历史。自动整理需要配置模型并启动 worker；它会按经历分段后处理，不会让每句新话立刻成为记忆。

MCP 由模型选择是否调用；插件才负责发送前主动召回。没有相关内容时，召回可以为空。

## 安装能简化到什么程度？

目前仍需要准备运行环境、保存密钥并启动服务。没有电脑/服务器一行命令全自动安装注册、自动云盘同步或手机换机向导。

Windows 初次使用可先选原生 Python 路线；已有 Docker 的用户按对应教程运行。不要为了改用另一条路线而覆盖原数据。
